[ 01 / a* search ]

A* Search Algorithm

1. Definition & Core Idea

  • A* is a best-first search algorithm that finds the shortest path by combining the actual cost from start (g(n)) with an estimated cost to goal (h(n), the heuristic). It evaluates nodes using the formula: f(n) = g(n) + h(n).
  • It is called "informed search" because it uses problem-specific knowledge (the heuristic) beyond the graph structure itself, unlike BFS/DFS/Uniform Cost Search which are uninformed.
  • A* expands the node with the lowest f(n) value first, maintained using a priority queue (open list), making it both efficient and accurate when the heuristic is well-chosen.
Evaluation function: f(n) = g(n) + h(n)  —  g(n) = cost so far from start, h(n) = estimated remaining cost to goal, f(n) = estimated total cost of a path through n.

2. Algorithm Steps

  • Step 1: Initialize an open list (priority queue) with the start node; set its g = 0 and compute f = g + h.
  • Step 2: Repeatedly pick the node with the minimum f(n) from the open list, move it to the closed list (visited set).
  • Step 3: If the picked node is the goal, terminate — path found is optimal. Otherwise, expand its neighbors, calculating their g, h, f values.
  • Step 4: For each neighbor, if a shorter path is found than previously recorded, update its g(n) and parent pointer; push it into the open list.
  • Step 5: Repeat until the open list is empty (no solution) or the goal is reached.

3. Worked Example

  • Consider a graph: S → A → B → G, with edge costs S-A=1, A-B=2, B-G=3, and heuristics h(S)=6, h(A)=4, h(B)=2, h(G)=0.
  • At S: f(S) = 0+6 = 6. Expand to A: f(A) = 1+4 = 5.
  • At A: expand to B: f(B) = 3+2 = 5. At B: expand to G: f(G) = 6+0 = 6.
  • Since f(G) = actual cost (no overestimation occurred), A* returns path S-A-B-G with cost 6, confirming it picked the least-cost path by always exploring the lowest f-value frontier node.

4. Optimality of A*

  • A* is optimal (guarantees the least-cost path) if the heuristic h(n) is admissible — meaning it never overestimates the true cost to reach the goal, i.e., h(n) ≤ h*(n) for all n.
  • Proof sketch: Suppose a suboptimal goal G2 is expanded before the optimal goal G. Since h(G2)=0, f(G2)=g(G2). Because h is admissible, for any node n on the optimal path, f(n) ≤ f(G) < f(G2). Hence A* would always pick n before G2, contradicting the assumption — proving optimality.
  • For graph search (with repeated states), A* requires the heuristic to also be consistent (monotonic): h(n) ≤ c(n,n') + h(n') for every edge — this ensures f(n) never decreases along any path, guaranteeing correctness without needing to reopen closed nodes.
  • Key properties summary: A* is complete (finds a solution if one exists), optimal (with admissible/consistent h), and optimally efficient (expands fewest nodes among algorithms using the same heuristic).

[ 02 / depth-limited search ]

Depth-Limited Search (DLS)

1. Definition & Core Idea

  • Depth-Limited Search (DLS) is a variant of DFS that solves DFS's problem of running infinitely down one path by imposing a predetermined depth limit ℓ, beyond which nodes are not expanded.
  • Nodes at depth ℓ are treated as if they have no successors, even if the goal lies deeper — this makes DLS incomplete if ℓ < depth of shallowest goal.
  • It is essentially DFS + a cutoff parameter, giving it controlled memory usage while avoiding the infinite-path trap of plain DFS on graphs with cycles or unbounded depth.

2. Algorithm / Working

  • Step 1: Start at the root node with depth = 0; treat it like standard DFS, expanding the leftmost unexpanded node first.
  • Step 2: At each node, check if current depth = ℓ (limit). If yes, stop expanding that branch — return "cutoff" signal instead of failure.
  • Step 3: If the goal is found within the limit, return the solution path.
  • Step 4: If a branch is exhausted (no more children, not at limit) and goal not found, backtrack — try the next sibling node.
  • Step 5: If all branches return either failure or cutoff without finding the goal, DLS reports the final result accordingly — distinguishing "no solution exists" from "solution may exist beyond limit."

3. Worked Example

  • Consider a tree: A → (B, C); B → (D, E); C → (F, G); goal is G, with limit ℓ = 2.
  • DLS starts at A (depth 0) → expands B (depth 1) → expands D, E (depth 2) — since depth = ℓ, both are treated as leaf nodes (cutoff), no further expansion even if they had children.
  • Backtrack to A, expand C (depth 1) → expand G (depth 2) — goal found! Since depth(G) = 2 = ℓ, it is reachable within the limit, so DLS returns path A-C-G.
  • Had the goal been at depth 3, DLS would fail to find it and report cutoff, even though a solution exists — illustrating its incompleteness when ℓ is chosen too small.

[ 03 / best-first search ]

Best-First Search (Informed / Greedy)

1. Definition & Core Idea

  • Best-First Search is a heuristic/informed search strategy that selects the "most promising" node to expand next, using an evaluation function f(n) to rank nodes — unlike uninformed search which expands nodes blindly (e.g., FIFO/LIFO order).
  • It uses a priority queue (open list), always picking the node with the lowest (or highest) f(n) value, making it greedy in nature — it chooses what looks best at the moment, without guaranteeing global optimality.
  • The most common form is Greedy Best-First Search, where f(n) = h(n) — purely the heuristic estimate of cost to reach the goal, ignoring the cost already incurred (g(n)).

2. Algorithm / Working

  • Step 1: Initialize the open list with the start node; compute its h(n) value using the chosen heuristic function.
  • Step 2: Repeatedly remove the node with minimum h(n) from the open list and place it in the closed list (visited).
  • Step 3: If this node is the goal, terminate and return the path found via parent pointers.
  • Step 4: Otherwise, generate successors, compute their h(n) values, and insert them into the priority queue (skip if already visited, depending on implementation).
  • Step 5: Repeat until the goal is found or the open list becomes empty (failure — no solution).

3. Worked Example

  • Consider nodes S (start) → A, B → G (goal), with straight-line heuristic estimates: h(S)=10, h(A)=6, h(B)=8, h(G)=0.
  • At S, successors are A (h=6) and B (h=8) — Greedy BFS picks A first since it has the lower h(n), ignoring actual edge costs.
  • From A, suppose it connects to G — since h(G)=0 is the lowest possible, G is selected next and search terminates.
  • Final path: S → A → G — chosen purely because h(n) kept decreasing, demonstrating the "greedy" behavior of always moving toward the seemingly closest node to goal.

4. Key Characteristics & Heuristic Angle

  • Completeness: Not complete in general (can get stuck in loops or dead ends on infinite graphs), unless combined with visited-node checking.
  • Optimality: Not optimal — since it ignores g(n) (path cost so far), it can be misled by a heuristic into a longer overall path, unlike A* which balances both g(n) and h(n).
  • Time & Space Complexity: O(bm) in the worst case (b = branching factor, m = max depth), since a poor heuristic can cause it to explore almost as much as uninformed search.
  • Heuristic dependency: Performance is entirely dependent on the quality of h(n) — a good heuristic (close to true cost) gives near-linear performance, while a poor/misleading heuristic can perform worse than BFS/DFS.

5. Comparison Note common follow-up

  • Greedy Best-First = f(n) = h(n) → fast but not optimal.
  • A* = f(n) = g(n) + h(n) → optimal (with admissible h), since it corrects greedy's flaw by also accounting for cost already spent.
Exam key line "Best-First Search is a generalized framework; Greedy BFS and A* are both special cases distinguished by their evaluation function f(n)."

[ 04 / uninformed search ]

Uninformed Search Strategies — BFS, DFS, UCS

1. Definition & Core Idea

  • Uninformed (Blind) Search strategies have no additional information about the goal beyond the problem definition — they only know how to distinguish a goal from a non-goal state, unlike informed search which uses a heuristic function.
  • They differ only in the order in which nodes are expanded, controlled by the data structure used for the fringe/frontier — a Queue (FIFO) for BFS, a Stack (LIFO) for DFS, and a Priority Queue for UCS.
  • Despite being simple, these strategies form the foundation for more advanced informed algorithms like A* and Greedy Best-First Search.

2. Breadth-First Search (BFS)

  • Expands the shallowest unexpanded node first using a FIFO queue — explores all nodes at depth d before moving to depth d+1, level by level.
  • Complete: Yes (if branching factor b is finite). Optimal: Yes, only if all step costs are equal/uniform.
  • Time/Space Complexity: O(bd) for both — major drawback is exponential space, since it must store all nodes at the current frontier level.

3. Depth-First Search (DFS)

  • Expands the deepest unexpanded node first using a LIFO stack, diving down one branch fully before backtracking to try others.
  • Complete: No (fails on infinite or cyclic state spaces unless depth-limited). Optimal: No — finds a solution, not necessarily the cheapest.
  • Time Complexity: O(bm), m = max depth (can be worse than BFS if m >> d). Space Complexity: O(bm) — much better than BFS, its biggest advantage.

4. Uniform Cost Search (UCS)

  • Expands the node with the lowest cumulative path cost g(n) first (not depth), using a priority queue — essentially Dijkstra's algorithm applied to search.
  • Complete: Yes (if step costs ≥ small positive constant ε). Optimal: Yes, always — regardless of step cost uniformity, since it always expands cheapest path first.
  • Time/Space Complexity: O(b1+⌊C*/ε⌋), where C* is optimal solution cost — can be far worse than BFS when step costs vary greatly.

6. Tree Search vs Graph Search pseudocode angle

  • Tree Search does not track visited/explored nodes — it may re-expand the same state repeatedly, causing infinite loops on cyclic graphs and redundant work.
tree-searchno explored set
function TREE-SEARCH(problem):
    frontier ← {initial state of problem}
    loop:
        if frontier is empty → return failure
        node ← REMOVE-CHOICE(frontier)
        if GOAL-TEST(node) → return SOLUTION(node)
        frontier ← INSERT-ALL(EXPAND(node), frontier)
  • Graph Search adds an "explored set" (closed list) — before expanding a node, it checks if the state was already visited, preventing repeated states and infinite loops.
graph-searchwith explored set
function GRAPH-SEARCH(problem):
    frontier ← {initial state}; explored ← {}
    loop:
        if frontier is empty → return failure
        node ← REMOVE-CHOICE(frontier)
        if GOAL-TEST(node) → return SOLUTION(node)
        add node to explored
        for each successor in EXPAND(node):
            if successor not in frontier ∪ explored:
                frontier ← INSERT(successor, frontier)
Key exam line: "Graph Search = Tree Search + explored set" — this trade-off costs extra memory (storing the explored set) but guarantees termination and avoids redundant computation on graphs with cycles/repeated states.

[ 05 / 8-puzzle ]

8-Puzzle Problem — Formulation & Heuristics

1. Problem Description

  • The 8-puzzle consists of a 3×3 board with 8 numbered tiles (1–8) and one blank space; a tile adjacent to the blank can slide into it, and the goal is to reach a specified goal configuration from a given initial configuration.
  • It is a classic toy problem used to illustrate and benchmark search algorithms, especially heuristic/informed search like A* and Greedy Best-First Search, since its state space is large (9!/2 ≈ 181,440 reachable states) but small enough to analyze.

2. Standard Problem Formulation

  • States: A state description specifies the location of each of the 8 tiles and the blank in the 3×3 grid (one of the 9 positions).
  • Initial State: Any configuration of the board can be designated as the start state — e.g., a given scrambled arrangement of tiles.
  • Actions/Operators: Defined in terms of the blank's movement — {Left, Right, Up, Down} (move the blank left, right, up, or down), with illegal moves (moving off the grid) simply not generated at the boundary.
  • Transition Model: Given a state and an action, returns the resulting state — i.e., swaps the blank with the adjacent tile in the specified direction.
  • Goal Test: Checks whether the current state matches the specified goal configuration (a particular arrangement of tiles, e.g., 1–8 in order with blank in a corner).
  • Path Cost: Each move costs 1, so the path cost equals the number of moves (steps) made from initial to goal state — making this an unweighted/uniform cost problem.

3. Deriving a Heuristic — Relaxed Problem Approach

  • A relaxed problem is created by removing or loosening constraints from the original problem — the cost of an optimal solution to the relaxed problem is an admissible heuristic for the original, since it never overestimates true cost (fewer restrictions ⇒ cheaper or equal solution).
  • Heuristic 1 — h1(n) = Number of misplaced tiles: Obtained by relaxing the rule "a tile can move only to the adjacent blank square" to "a tile can move anywhere" — then the solution cost = number of tiles out of place, since each misplaced tile needs at least one move.
  • Heuristic 2 — h2(n) = Manhattan Distance (sum of distances of tiles from goal): Obtained by relaxing the rule to "a tile can move to any adjacent square (even if occupied)" — then each tile can move independently in a straight line, so the cost = sum of |Δx|+|Δy| for each tile from its current to goal position.
  • Dominance: h2 (Manhattan) dominates h1 (misplaced tiles) — i.e., h2(n) ≥ h1(n) for all n — because Manhattan distance accounts for how far a tile is, not just whether it's misplaced; a dominant heuristic is always preferred since it expands fewer nodes while remaining admissible.

4. Why Relaxation Works key theoretical point

  • Key principle: "If the rules of the original problem are a subset of the rules of the relaxed problem (i.e., it has fewer restrictions on action), then any solution to the original problem is also a solution to the relaxed problem." Hence the optimal relaxed solution ≤ optimal real solution, guaranteeing admissibility.
  • Automated heuristic generation: This relaxation technique can be mechanically applied via problem-description languages — tools can strip preconditions from actions to automatically generate admissible heuristics, rather than needing hand-crafted ones.
Exam key line "A heuristic derived from a relaxed version of the original problem is never larger than the true cost, hence always admissible — making both h1 and h2 valid for use in A* search."

[ 06 / performance measures ]

Parameters for Evaluating a Search Algorithm

1. Why Evaluate Search Algorithms?

  • A search algorithm's quality cannot be judged by speed alone — it must be assessed on multiple independent dimensions, since an algorithm good on one measure may fail badly on another (e.g., DFS saves space but sacrifices completeness/optimality).
  • These four standard criteria allow systematic comparison between strategies like BFS, DFS, UCS, A* — and are almost always asked together as a package in exams.

2. Completeness

  • Completeness asks: "Is the algorithm guaranteed to find a solution whenever one exists?" — an algorithm is complete if it never fails to find a goal in a finite search space (or infinite space with proper safeguards).
  • Example: BFS is complete (finite branching factor) since it explores level by level, but DFS is incomplete on infinite-depth or cyclic spaces since it can get stuck going down one infinite path and never backtrack to find the goal.

3. Optimality

  • Optimality asks: "Does the algorithm find the least-cost solution among all possible solutions?" — being complete does not imply optimal (a solution may be found, but not the cheapest).
  • Example: UCS is always optimal (expands lowest g(n) first, like Dijkstra), BFS is optimal only if step costs are uniform, while DFS and Greedy Best-First are generally not optimal.

4. Time Complexity

  • Time Complexity measures how long the algorithm takes to find a solution — typically expressed as the number of nodes generated/expanded, as a function of problem parameters: branching factor (b), depth of shallowest goal (d), maximum depth (m).
  • Example: BFS/UCS = O(bd), DFS = O(bm) — note that if m >> d, DFS can be far worse, but if the goal is deep and few paths dead-end, DFS may be faster in practice despite the same worst-case class.

5. Space Complexity

  • Space Complexity measures the maximum size of memory (frontier + explored set) needed during search — often the real bottleneck in practice, since time can be waited out but memory cannot be exceeded.
  • Example: BFS requires O(bd) space (must store the entire frontier, which grows exponentially), while DFS needs only O(bm) — this memory efficiency is DFS's primary practical advantage despite weaker completeness/optimality.

7. Key Exam Takeaway

  • No single algorithm dominates on all four measures — choosing a search strategy involves a trade-off: BFS/UCS guarantee correctness (complete + optimal) at the cost of exponential memory, while DFS trades correctness for memory efficiency.
  • b (branching factor), d (shallowest goal depth), and m (maximum tree depth) are the three key parameters that every complexity formula is built from — always define these explicitly in the answer for full marks.
