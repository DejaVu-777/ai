01 PEAS Description for a Given Agent

PEAS is the standard way to pin down a task environment before you design anything. Practise the method, not the examples — soccer, auction, part-picking robot, English tutor and self-driving car are just five ways of applying the same four questions.

1. Definition write this first

PEAS stands for Performance measure, Environment, Actuators, Sensors — a framework used to formally describe a task environment for a rational agent. It helps in designing an agent by clearly specifying what it should achieve and how it perceives and acts in its world.

The examiner looks for this line before anything else.

2. Meaning of Each Component define before applying

  • Performance Measure: The criterion of success — what the agent is trying to maximize/achieve (e.g., efficiency, safety, accuracy). Always list this first since every other element serves this goal.
  • Environment: The external surroundings the agent operates in — includes objects, other agents, and conditions it must perceive and react to.
  • Actuators: The mechanisms through which the agent acts on the environment (motors, screens, speakers, arms).
  • Sensors: The mechanisms through which the agent perceives the environment (cameras, microphones, GPS, keyboards).

3. Method to Apply PEAS the examinable trick

  • Ask: "What is it supposed to accomplish?" → Performance Measure.
  • Ask: "Where does it operate and what's around it?" → Environment.
  • Ask: "What can it do/output?" → Actuators.
  • Ask: "What can it sense/input?" → Sensors.

02 Goal-Based Agent & Utility-Based Agent

1. Goal-Based Agent

  • A goal-based agent acts not just on current percepts but also considers a goal/desired state, choosing actions that will lead it closer to achieving that goal. It requires information about "what it is trying to achieve" in addition to the current state.
  • It involves search and planning — the agent considers future consequences of actions before deciding, unlike simpler reflex agents that react immediately.
  • Useful when multiple paths exist but only some achieve the goal; the agent evaluates and selects the action sequence that satisfies it.

2. Utility-Based Agent

  • A utility-based agent goes a step further — instead of a binary goal (achieved/not achieved), it uses a utility function that maps a state to a real number measuring "degree of happiness" or desirability.
  • It is needed when goals are insufficient — e.g., multiple goals conflict, or several paths achieve the goal but with different cost, speed, risk, or safety — the agent picks the action with maximum expected utility.
  • Enables rational decision-making under trade-offs and uncertainty, often combined with probability (expected utility maximization).

03 Task Environment Types

1. Introduction

  • A task environment is characterized along several key dimensions that determine the design complexity of the rational agent needed to operate in it. These properties are not mutually exclusive and together decide the difficulty level of the environment.

2. The Six Dimensions define + example each

  • Fully Observable vs. Partially Observable
    • Fully observable: Agent's sensors give complete access to the environment's state at every point in time — nothing relevant is hidden. Example: Chess (board fully visible).
    • Partially observable: Sensors give incomplete/noisy data, or parts of the state are hidden. Example: Poker (opponent's cards hidden), self-driving car (can't see beyond obstructions).
  • Deterministic vs. Stochastic
    • Deterministic: The next state is completely determined by the current state and the agent's action — no randomness involved. Example: Vacuum cleaner world (idealized), puzzle solving.
    • Stochastic: Outcomes involve uncertainty/randomness — the same action may lead to different results. Example: Self-driving car (traffic, weather), dice games.
  • Episodic vs. Sequential
    • Episodic: Agent's experience is divided into atomic, independent episodes — current action does not depend on previous ones. Example: Part-picking robot (each part sorted independently), image classification.
    • Sequential: Current decision affects future decisions — actions have long-term consequences. Example: Chess, self-driving car.
  • Static vs. Dynamic
    • Static: The environment does not change while the agent is deliberating — only the agent's actions change the world. Example: Crossword puzzle.
    • Dynamic: The environment changes over time independent of the agent's actions, demanding continuous monitoring. Example: Self-driving car, soccer game. (Semi-dynamic: environment static but performance score changes with time, e.g., chess with a clock.)
  • Discrete vs. Continuous
    • Discrete: A finite/countable number of distinct states, percepts, and actions. Example: Chess (fixed positions/moves).
    • Continuous: States, time, or actions take on an infinite range of values. Example: Self-driving car (continuous speed, steering angles).
  • Single-agent vs. Multi-agent
    • Single-agent: Only one agent operates, solving problems independently. Example: Crossword puzzle solver.
    • Multi-agent: Multiple agents interact, which may be competitive (chess — opponent) or cooperative (soccer teammates). Example: Auction (competitive), soccer (both).

  • Don't just define — always pair definition with a one-word example; bare definitions lose application marks.

04 Learning Agent

1. Introduction

  • A learning agent is one that can improve its performance over time through experience, rather than relying solely on a fixed, pre-programmed behavior. It allows the agent to operate in unknown environments and become more competent than its initial knowledge would allow.
  • This is considered the most general and advanced agent design, since it can be built on top of any other agent type (reflex, goal-based, utility-based) to make it adaptive.

2. Four Main Components define each

  • Learning Element
    • Responsible for making improvements to the agent's behavior based on feedback received. It uses the critic's feedback to modify the performance element for better future decisions.
  • Performance Element
    • This is the part that selects external actions — essentially, it is the "whole agent" from earlier designs (simple reflex, goal-based, utility-based). It takes percepts and decides actions.
  • Critic
    • Provides feedback to the learning element by evaluating how well the agent is doing with respect to a fixed performance standard (external, not changed by the agent). It converts raw percepts into a performance judgment.
  • Problem Generator
    • Suggests exploratory/novel actions that may seem suboptimal in the short term but help the agent discover new, better strategies by gathering new experiences — essential for long-term learning rather than pure exploitation.

4. Working write as numbered flow

  • 1. The performance element receives percepts from sensors and selects actions via actuators, just like a standard agent.
  • 2. The critic observes the environment's response/outcome and compares it against a fixed performance standard, generating feedback on how well the agent performed.
  • 3. This feedback is passed to the learning element, which analyzes what went right/wrong and modifies the performance element accordingly — improving future decision-making.
  • 4. The problem generator meanwhile suggests new, exploratory actions (not necessarily optimal now) so the agent doesn't get stuck in a suboptimal strategy and continues discovering better behavior over time.
Quick exam strategy
  • Always mention the "4 components" by name first before the diagram — many students draw the diagram but forget to define each block, losing marks.
  • Use the one-line analogy: "Performance element = does the job; Critic = judges the job; Learning element = fixes the job; Problem generator = tries new things" — easy to recall under exam pressure.
  • Emphasize: learning agent converts ANY fixed agent into an adaptive one — a favorite follow-up/viva question.

05 Simple Reflex & Model-Based Reflex Agents

1. Simple Reflex Agent

  • A simple reflex agent selects actions based only on the current percept, ignoring the entire percept history. It works using condition-action rules (also called if-then rules): "if condition then action."
  • It is simple and fast but works correctly only if the environment is fully observable — since it has no memory, it cannot handle partial observability and can get stuck in infinite loops in such cases.
  • Example: A vacuum cleaner agent that cleans if it senses dirt, else moves — reacts purely on current percept, not past states.

2. Model-Based Reflex Agent

  • A model-based reflex agent overcomes the limitation of partial observability by maintaining an internal state that tracks the part of the world it can't currently see, updated using knowledge of "how the world evolves" and "how its own actions affect the world."
  • This internal state is built using a model of the world — hence the name — which consists of two kinds of knowledge: transition model (how the world changes) and sensor model (how percepts reflect world state).
  • It is more capable than simple reflex agents in handling partially observable environments, since it can "remember" relevant unseen aspects of the world rather than reacting blindly.

Quick exam strategy
  • Always highlight the "no memory vs. has memory" distinction as the single biggest differentiator — this is the most commonly asked comparison point.
  • In the diagram, the key addition in model-based is the two extra boxes — "how the world evolves" and "what my actions do" — feeding into the state block; draw and label these clearly for full marks.
  • Remember: both agents still use condition-action rules for final decision — the difference lies only in how "current state" is determined (direct percept vs. updated internal model).

06 Applications of AI

1. Introduction

  • Artificial Intelligence (AI) has moved from theoretical research to widespread real-world deployment, with intelligent agents now performing tasks that rival or exceed human capability in specific domains. The following are key application areas, each demonstrating a different aspect of agent design (search, learning, perception, reasoning).

2. Key Applications 3–5, one line each

  • Autonomous Vehicles (Self-Driving Cars)
    • Uses sensors (LIDAR, camera, GPS) and real-time decision-making to navigate roads, avoid obstacles, and obey traffic rules without human intervention — a classic example of a utility-based, learning agent.
  • Natural Language Processing (NLP) / Virtual Assistants
    • Systems like Siri, Alexa, and ChatGPT understand and generate human language, enabling voice commands, translation, and conversational interaction.
  • Medical Diagnosis Systems
    • AI analyzes medical images (X-rays, MRIs) and patient data to detect diseases (e.g., cancer detection) faster and often more accurately than manual review, assisting doctors in diagnosis.
  • Game Playing
    • Programs like Deep Blue (chess) and AlphaGo (Go) use search algorithms and learning to defeat human champions, demonstrating AI's strength in adversarial, sequential decision-making.
  • Robotics (Industrial & Service Robots)
    • Part-picking robots, warehouse automation (Amazon robots), and surgical robots perform precise physical tasks, combining perception (vision) and actuation in real-world environments.
  • Spam Filtering / Recommendation Systems
    • Email services use AI to classify spam vs. legitimate mail, while platforms like Netflix and Amazon use machine learning to recommend content/products based on user behavior.
Quick exam strategy
  • Pick 4–5 diverse examples covering different domains (transport, language, healthcare, gaming, robotics) rather than 5 similar ones — shows breadth of understanding.
  • For each, mention one AI technique used (e.g., search, learning, NLP, computer vision) — this links the application back to AI concepts, earning bonus marks.
  • If time permits, add one line on impact: "AI applications demonstrate the shift from rule-based systems to adaptive, learning-based intelligent agents."
