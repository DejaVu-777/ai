01 Cryptarithmetic as CSP — SEND + MORE = MONEY

The single most repeated numerical in the whole exam. Solve it by hand using backtracking + forward checking + MRV / least-constraining-value heuristics.

1. Problem Formulation (CSP definition)

  • Variables: S, E, N, D, M, O, R, Y (8 letters → 8 variables).
  • Domain: {0,1,2,...,9} for each variable, with M ≠ 0 and S ≠ 0 (no leading zeros).
  • Constraints: All-Diff (all letters take distinct digits) + the arithmetic column constraint that the sum of SEND and MORE equals MONEY.

2. Column Equations (with carries c1–c4)

  • Column 1 (units): D + E = Y + 10·c1
  • Column 2 (tens): N + R + c1 = E + 10·c2
  • Column 3 (hundreds): E + O + c2 = N + 10·c3
  • Column 4 (thousands): S + M + c3 = O + 10·c4
  • Column 5 (ten-thousands): c4 = M

3. Applying MRV (Minimum Remaining Values)

  • MRV picks the variable with the smallest legal domain first. M is chosen first because column 5 forces c4 = M, and since the maximum possible carry is 1, M's domain collapses instantly to {1} — this is the most constrained variable.
  • Next, S is selected (highly constrained by column 4: S + M + c3 = O + 10). Using forward checking, S's domain shrinks to {8, 9} only.

4. Applying LCV (Least Constraining Value) + Forward Checking

  • LCV prefers the value that rules out the fewest options for neighboring variables. Trying S = 9 (instead of 8) leaves more flexibility downstream, so it's chosen first.
  • With M=1, S=9: column 4 gives 9 + 1 + c3 = O + 10 → O = 0 (since O≠M, O≠S, this is consistent — forward checking confirms no domain wipeout).

5. Backtracking Trace (remaining letters)

  • From column 3 (E + O + c2 = N + 10c3), since O=0, this simplifies to E + c2 = N + 10c3. Testing c3=0 → E = N (violates All-Diff) → backtrack, set c3 = 1, giving N = E + c2 − 10... → N = E+1 (after checking c2 possibilities via forward checking).
  • From column 2 (N + R + c1 = E + 10c2): substituting N = E+1 and testing c2=1 (forced since c3=1 needs support) gives R = 8, c1 = 1.
  • From column 1 (D + E = Y + 10c1), with c1=1: D + E = Y + 10. Testing remaining domain values (forward checking eliminates clashing digits) yields E = 5, N = 6, D = 7, Y = 2.

6. Final Consistent Assignment

S=9, E=5, N=6, D=7, M=1, O=0, R=8, Y=2
Verification: 9567 + 1085 = 10652 ✔ — all digits distinct, no constraint violated.

7. Why Backtracking + FC + MRV/LCV Together examiner magnet

  • Backtracking alone explores depth-first and undoes bad assignments (like the S=8 dead-end); Forward Checking prunes domains of unassigned neighbors immediately after each assignment to detect failure early; MRV decides which variable to assign next (most constrained first); LCV decides which value to try (least restrictive first) — together they drastically cut the search space compared to naive brute-force backtracking.

02 Alpha-Beta Pruning on a Game Tree

1. Concept Recap examiner checks this first

  • Alpha-Beta Pruning is an optimization over the Minimax algorithm that eliminates branches which cannot influence the final decision, without changing the computed minimax value.
  • α (alpha) = the best (highest) value found so far for MAX along the path; β (beta) = the best (lowest) value found so far for MIN. A branch is pruned whenever α ≥ β.

2. The Game Tree left-to-right move order

Fig. 1MAX / MIN alternating tree
                 Root (MAX)
              /              \
          B (MIN)           C (MIN)
         /      \           /      \
     D(MAX)   E(MAX)     F(MAX)   G(MAX)
     /  \      /  \       /  \     /  \
    3    5    6    9     1    2   0   -1

swipe diagram →

3. Step-by-Step Pruning Trace (left-to-right DFS)

  • Node D: leaves 3, 5 explored → D's α updates 3→5 → D = 5. (No pruning possible here, nothing to compare against yet.)
  • Node B (MIN): receives D=5, so β(B) = 5. This β=5 is passed down to sibling E.
  • Node E: first leaf 6 → E's local α = 6. Since α(6) ≥ β(5), PRUNE — the second leaf 9 is never evaluated (Alpha cut-off). E returns 6, but it's irrelevant since B already has a better (lower) option.
  • Node B final = min(5, 6) = 5. Root updates α(root) = 5.
  • Node F (MAX), under C, inherits α=5, β=∞: leaves 1, 2 both explored (neither triggers pruning inside F) → F = 2.
  • Node C (MIN): updates β(C) = min(∞, 2) = 2. Now check against root's α=5: since β(2) ≤ α(5), PRUNE — sibling G (leaves 0, −1) is never explored (Beta cut-off).
  • Root (MAX) = max(B=5, C=2) = 5 → Final Minimax Value = 5.

5. Key Observations examiners reward

  • Alpha-beta pruning returns the same final value (5) as plain minimax but evaluates fewer nodes — here 2 leaves out of 8 were skipped.
  • Move ordering matters critically: exploring the best move first maximizes pruning; with perfect ordering, time complexity improves from O(bd) to O(bd/2), effectively doubling the usable search depth.
  • The pruning condition differs by node type: MAX nodes prune when value ≥ β; MIN nodes prune when value ≤ α — this asymmetry is a common trick question.

03 AC-3 (Arc Consistency Algorithm)

1. Concept Definition

  • AC-3 (Arc Consistency Algorithm #3) is a constraint propagation technique used to reduce variable domains in a CSP before or during search, by enforcing that every arc (binary constraint) is consistent.
  • An arc X → Y is said to be arc-consistent if for every value x in Dom(X), there exists some value y in Dom(Y) that satisfies the constraint between X and Y. If not, x is removed from Dom(X).

2. The Algorithm write exactly

  • Step 1: Initialize a queue with all arcs in the CSP (each binary constraint generates two directed arcs, e.g., X→Y and Y→X).
  • Step 2: Pop an arc (Xi, Xj) from the queue and call REVISE(Xi, Xj).
  • Step 3 — REVISE procedure: For each value x in Dom(Xi), check if there exists a value y in Dom(Xj) satisfying the constraint. If no such y exists, delete x from Dom(Xi).
  • Step 4: If REVISE changed Dom(Xi) (domain got smaller), re-add all arcs (Xk, Xi) for every neighbor Xk of Xi (except Xj) back into the queue — since Xi's reduced domain might now make those arcs inconsistent.
  • Step 5: Repeat until the queue is empty (arc-consistent) or some domain becomes empty → CSP has no solution (failure detected early).

3. Worked Example numerical

  • Consider two variables: X ∈ {1, 2, 3}, Y ∈ {1, 2, 3}, with constraint X < Y.
  • Arc (X, Y): Check each value of X — X=1: Y=2 or 3 satisfies → keep. X=2: Y=3 satisfies → keep. X=3: no value of Y > 3 exists → delete 3 from Dom(X). Now Dom(X) = {1, 2}.
  • Arc (Y, X): Y=1: no X < 1 → delete 1 from Dom(Y). Y=2: X=1 works → keep. Y=3: X=1 or 2 works → keep. Now Dom(Y) = {2, 3}.
  • Since Dom(X) changed, re-check arcs pointing into X (none here other than already processed) — queue empties. Final domains: X={1,2}, Y={2,3} — this is now arc-consistent (though not yet a complete solution).

4. Complexity

  • With n variables, d domain size, and c binary constraints, AC-3 runs in O(c·d³) time — each arc can be pushed back onto the queue O(d) times, and REVISE costs O(d²).

5. Key Role in CSP Solving

  • AC-3 is typically applied as a preprocessing step or interleaved with backtracking search (MAC – Maintaining Arc Consistency) to shrink domains early and detect dead-ends without full search.
  • It does not guarantee a solution by itself (a CSP can be arc-consistent yet still have no valid assignment, e.g., in cases needing path-consistency or higher-order checks) — it only eliminates values that can never be part of any solution, making subsequent backtracking far more efficient.

04 Minimax Search

1. Concept Definition

  • Minimax is a decision-making algorithm used in two-player, zero-sum, perfect-information games (like chess, tic-tac-toe) where one player (MAX) tries to maximize the outcome and the other (MIN) tries to minimize it, assuming both players play optimally.
  • It works by recursively exploring the game tree to the terminal nodes (leaves), then backing up values level by level to decide the best move at the root.

2. The Algorithm

  • Step 1: Generate the complete game tree from the current state down to terminal states (or a fixed depth limit with a heuristic evaluation function if the tree is too large).
  • Step 2: Assign utility values to terminal/leaf nodes (e.g., +1 = win for MAX, −1 = win for MIN, 0 = draw).
  • Step 3: Backpropagate values upward — at a MAX node, take the maximum of its children's values; at a MIN node, take the minimum of its children's values.
  • Step 4: The value propagated to the root represents the best achievable outcome; the root chooses the child branch that leads to this value as its move.

3. Worked Example

Fig. 2Minimax tree
                MAX (root)
             /              \
          MIN A            MIN B
         /     \           /     \
        3       5         2       9

swipe diagram →

  • Node A (MIN): children are leaves 3 and 5 → MIN picks the smaller → A = min(3,5) = 3.
  • Node B (MIN): children are leaves 2 and 9 → MIN picks the smaller → B = min(2,9) = 2.
  • Root (MAX): compares A=3 and B=2 → MAX picks the larger → Root = max(3,2) = 3.
  • Decision: MAX should choose the branch toward Node A, guaranteeing a payoff of 3, since MIN will always counter optimally to minimize MAX's gain.

4. Minimax Formula

  • For a MAX node: Minimax(n) = max( Minimax(c) ) for all children c of n.
  • For a MIN node: Minimax(n) = min( Minimax(c) ) for all children c of n.
  • For a terminal node: Minimax(n) = Utility(n).

5. Complexity

  • Time complexity: O(bm) — where b = branching factor, m = maximum depth of the tree (since it explores every node exhaustively).
  • Space complexity: O(bm) (linear) if using depth-first exploration, since only one path needs to be stored at a time.

6. Key Observations examiner magnet

  • Minimax guarantees an optimal move only if the opponent also plays optimally; it does not account for probabilistic or suboptimal opponents.
  • Pure minimax is computationally expensive for large games (e.g., chess has branching factor ~35) — this limitation motivates Alpha-Beta Pruning, which computes the same result while exploring fewer nodes.

05 Local Consistency — Node, Arc, Path

1. Concept Definition

  • Local consistency techniques check and enforce consistency over small subsets of variables (1, 2, or 3 at a time) before/during search, pruning the search space by eliminating values that can never appear in any valid solution — without solving the whole CSP.
  • The three standard levels, in increasing order of strength, are: Node Consistency → Arc Consistency → Path Consistency.

2. Node Consistency 1st order — unary

  • A variable is node-consistent if every value in its domain satisfies that variable's own unary constraints.
  • Example: If domain of X = {1,2,3,4,5} and the constraint is X > 2, then node consistency removes 1 and 2, leaving Dom(X) = {3,4,5}.
  • This is the weakest and simplest form — it only looks at a single variable in isolation, never considering relationships between variables.

3. Arc Consistency 2nd order — binary

  • An arc X → Y is consistent if for every value x in Dom(X), there exists some value y in Dom(Y) satisfying the binary constraint between them. If no such y exists, x is removed.
  • Example: X ∈ {1,2,3}, Y ∈ {1,2,3}, constraint X < Y. For X=3, no Y > 3 exists → remove 3 from Dom(X). Resulting Dom(X) = {1,2}.
  • Enforced via the AC-3 algorithm; it is stronger than node consistency since it considers pairs of variables, but still doesn't guarantee a full solution (a CSP can be arc-consistent yet unsolvable).

4. Path Consistency 3rd order — triples

  • A pair of variables {X, Y} is path-consistent with respect to a third variable Z if, for every consistent assignment to X and Y, there exists a value of Z that satisfies the constraints X–Z and Z–Y simultaneously.
  • Example: X, Y, Z all ∈ {1,2,3} with constraints X≠Y, Y≠Z, X≠Z (like a 3-coloring problem) — path consistency checks whether every valid (X,Y) pair can be extended to include a valid Z, removing (X,Y) pairs that have no supporting Z.
  • This is stronger than arc consistency because it reasons over 3 variables jointly, catching inconsistencies that arc consistency misses — but it is also more computationally expensive.

6. Key Observations examiner magnet

  • Higher-order consistency ⇒ more pruning ⇒ smaller search space, but also higher computational cost — there's a direct trade-off between consistency strength and processing time.
  • None of these techniques alone guarantees a solution; they are used as preprocessing or interleaved steps (e.g., combined with backtracking search) to make CSP solving dramatically more efficient, since full consistency (k-consistency for all k) is equivalent to solving the CSP outright — which is computationally infeasible for large problems.

06 Constructing a Tree from a CSP Graph

1. Concept Definition

  • A CSP constraint graph has variables as nodes and binary constraints as edges. If this graph is already a tree (no cycles), the CSP can be solved in linear time; if it has cycles, we must reduce it to a tree form using Cutset Conditioning or Tree Decomposition.
  • The key theorem: any tree-structured CSP can be solved in O(n·d²) time — linear in the number of variables, instead of the exponential cost of general CSPs.

2. Steps to Solve an Already-Tree-Structured CSP

  • Step 1 — Choose a root and perform a topological sort (ordering) of the tree so that every node appears after its parent (parent before children).
  • Step 2 — Directional Arc Consistency (backward pass): Process nodes from last to first (leaves → root). For each arc (Parent, Child), apply REVISE so the parent's domain only keeps values consistent with some value of the child — this removes values that would later cause failure.
  • Step 3 — Forward assignment pass: Process nodes from first to last (root → leaves). Assign each variable a value from its (now pruned) domain that is consistent with its already-assigned parent — this assignment is guaranteed never to backtrack.

3. Example — Tree-Structured CSP

Fig. 3Already a tree
        A
       / \
      B   C
     /
    D

swipe diagram →

  • Suppose all domains = {1,2}, with constraint "not equal" on every edge (A≠B, A≠C, B≠D).
  • Backward pass (D→B→C→A): Check D against B — fine, no removal. Check B against A — fine. Check C against A — fine. (No domain wipeout, tree is consistent.)
  • Forward pass (A→B→C→D): Assign A=1. Then B must ≠1 → B=2. Then C must ≠1 → C=2. Then D must ≠2 (its parent B) → D=1.
  • Final solution: A=1, B=2, C=2, D=1 — found without any backtracking.

4. Converting a General (Cyclic) Graph into a Tree — Cutset Conditioning

  • Step 1: Identify a Cycle Cutset — a minimal set of variables which, when removed, leaves the remaining graph cycle-free (a tree).
  • Step 2: For every possible value-assignment to the cutset variables, fix those values and check if the remaining tree-structured CSP can be solved (using the tree algorithm above).
  • Step 3: If a consistent assignment to the rest of the tree is found for some cutset assignment, that combined assignment is a solution; otherwise try the next combination of cutset values.

5. Example — Cutset Conditioning

Fig. 4Cycle graph → cutset
     A --- B
     |     |
     D --- C

swipe diagram →

  • This graph has a cycle (A-B-C-D-A). Removing A (the cutset, size 1) leaves B-C-D, a simple path (tree).
  • Try A=1 → remaining tree (B,C,D) is solved using the tree algorithm with A's value fixed as a constraint on B and D.
  • If no solution exists for A=1, try A=2, and repeat — since domain size is small, this requires only a few tree-solves, not full exponential search.

6. Complexity

  • If the cutset size is c and domain size is d, total complexity = O(dc · (n−c)·d²) — exponential only in c, so a small cutset makes this far more efficient than brute-force backtracking on the whole graph.

7. Key Observations examiner magnet

  • Tree-structured CSPs are solved in polynomial time; general CSPs are NP-hard — the entire motivation behind cutset conditioning and tree decomposition is to exploit sparse/tree-like structure hidden in real-world constraint graphs.
  • Finding the smallest cycle cutset is itself NP-hard, but heuristic methods usually find a reasonably small cutset quickly, making this approach practical despite the theoretical worst case.

07 Backtracking Search in CSPs

1. Concept Definition

  • Backtracking Search is a depth-first search strategy for CSPs that assigns values to variables one at a time, and whenever an assignment violates a constraint, it immediately abandons that branch and backtracks to try a different value — avoiding the need to explore the entire search space blindly.
  • It is a refinement of simple backtracking called the Backtracking Search Algorithm, which checks constraints incrementally after each assignment rather than generating a complete assignment first and testing it at the end.

2. The Algorithm write exactly

  • Step 1: If all variables are assigned, return the assignment as the solution (success).
  • Step 2: Else, select an unassigned variable (using a heuristic like MRV — Minimum Remaining Values).
  • Step 3: For each value in that variable's domain (ordered using LCV — Least Constraining Value):
    • Check consistency of this value against all already-assigned neighbors.
    • If consistent, assign it and recursively call backtracking on the remaining variables.
    • If the recursive call succeeds, return success.
    • If it fails, undo (backtrack) the assignment and try the next value.
  • Step 4: If no value works for this variable, return failure — forcing the previous level to backtrack further.

3. Worked Example map coloring

  • Consider 3 regions — A, B, C forming a triangle (all mutually adjacent), with colors {Red, Green} available, and constraint: adjacent regions must have different colors.
  • Assign A = Red (first variable, first value) → consistent so far (no neighbors assigned yet).
  • Assign B = Red? → conflict (B is adjacent to A, both Red) → try B = Green → consistent.
  • Assign C: must differ from both A (Red) and B (Green) → no color in {Red, Green} works → failure at C.
  • Backtrack to B: no other values left for B → backtrack to A: try A = Green instead.
  • Repeating the process: A=Green, B=Red, C=? → again no valid color for C (triangle with only 2 colors is unsolvable) → algorithm correctly returns "no solution exists" after exhausting all branches.

4. Improving Plain Backtracking

  • Variable Ordering (MRV): choose the variable with the fewest legal values remaining — fails fast, pruning the tree early.
  • Value Ordering (LCV): choose the value that rules out the fewest choices for neighboring variables — keeps maximum flexibility for future assignments.
  • Forward Checking: after each assignment, check remaining variables' domains and eliminate values that would conflict — detects failure earlier than plain backtracking.

5. Complexity

  • Worst-case time complexity: O(dn) — where d = domain size, n = number of variables (same as brute-force in the worst case), but in practice far faster due to early pruning of inconsistent branches.

6. Key Observations examiner magnet

  • Backtracking is complete (will find a solution if one exists) and avoids the massive redundancy of generate-and-test, since it detects constraint violations as early as possible in the assignment process.
  • It forms the base algorithm on which more powerful techniques — Forward Checking, MAC (Maintaining Arc Consistency), and heuristics like MRV/LCV/degree heuristic — are layered to achieve practical efficiency on large CSPs.
